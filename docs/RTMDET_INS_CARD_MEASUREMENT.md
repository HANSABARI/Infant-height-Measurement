# RTMDet-Ins 기반 카드 검출 및 픽셀-실측 변환 설계

## 1. 목적

이 프로젝트는 사진 속 사람의 키를 추정하기 위해 국제 표준 규격의 신용카드를 기준 물체로 사용한다.

전체 흐름은 다음과 같다.

1. 사진에서 카드를 검출한다.
2. 카드의 실제 긴 변인 `8.56 cm`가 이미지에서 몇 픽셀인지 계산한다.
3. `px/cm` 비율을 구한다.
4. 사람의 포즈 키포인트 간 픽셀 거리를 실제 길이로 변환한다.

핵심 식은 다음과 같다.

```text
px_per_cm = 카드의 긴 변 픽셀 길이 / 8.56 cm
실제 길이(cm) = 이미지상의 픽셀 길이 / px_per_cm
```

---

## 2. RTMDet-Ins를 사용한 이유

초기 카드 검출 방식은 일반 RTMDet 모델이 반환하는 축 정렬 바운딩 박스(axis-aligned bounding box)를 기준으로 카드 크기를 측정했다.

이 방식에는 다음 문제가 있다.

- 카드가 회전하면 bbox의 가로·세로 크기가 실제 카드 변 길이보다 커진다.
- 배경이 bbox 내부에 포함된다.
- 카드 모서리와 실제 외곽선을 알 수 없다.
- 비스듬한 카드에서 측정 오차가 커진다.

RTMDet-Ins는 객체 검출과 인스턴스 세그멘테이션을 함께 수행한다.

- bbox: 카드의 대략적인 위치
- mask: 카드에 해당하는 픽셀 영역

따라서 카드의 실제 외곽선을 기준으로 기하 정보를 계산할 수 있어, 실측 변환 기준을 만드는 목적에 일반 bbox 모델보다 적합하다.

RTMDet-Ins를 사용해도 bbox가 함께 반환되는 것은 정상이다. 화면에 bbox만 표시되었던 이유는 모델 문제가 아니라 기존 시각화 코드가 `cv2.rectangle()`만 호출했기 때문이다.

## 4. 카드 크기 계산 방식의 발전

### 4.1 bbox 긴 변 사용

초기 방식:

```text
long_side_px = max(bbox_width, bbox_height)
```

장점은 단순하고 빠르다는 것이지만, 카드가 회전할수록 bbox에 배경이 포함되어 길이가 과대 측정된다.

### 4.2 마스크의 최소 회전 사각형 사용

다음 단계에서는 카드 마스크의 외곽선을 구하고 `cv2.minAreaRect()`를 사용했다.

```text
mask
  → contour
  → minimum-area rotated rectangle
  → rectangle의 긴 변
```

축 정렬 bbox보다 회전에 강하고 카드 방향을 반영한다. 그러나 마스크의 한두 개 돌출 픽셀, 둥근 모서리, 외곽선의 작은 노이즈가 최소 회전 사각형 전체에 영향을 줄 수 있다.

### 4.3 단순 극단점 평균을 사용하지 않은 이유

마스크의 최대·최소 좌표 주변을 평균내는 방식도 노이즈를 줄일 수 있다. 하지만 다음 문제가 있다.

- 카드 모서리는 둥글기 때문에 평균점이 실제 모서리보다 안쪽으로 이동할 수 있다.
- 카드 회전 방향에 따라 x/y 극단값의 의미가 달라진다.
- 원근으로 사다리꼴이 된 카드의 네 변을 충분히 표현하지 못한다.
- 임의의 평균 범위에 따라 결과가 달라진다.

따라서 점 몇 개의 좌표를 평균내기보다, 각 변 주변의 여러 외곽점에 직선을 robust하게 피팅하는 방법을 선택했다.

## 5. 현재 방식: Robust line fitting

현재 구현은 다음 순서로 동작한다.

### 5.1 카드 인스턴스 선택

모델 결과 중 score threshold `0.3`을 초과한 객체를 고른 뒤, 가장 confidence가 높은 카드 하나를 선택한다.

### 5.2 마스크 변환

선택한 카드 마스크를 원본 이미지 크기의 이진 마스크로 변환한다.

```text
mask > 0.5 → 0 또는 1
```

### 5.3 외곽선 추출

```python
cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_NONE)
```

가장 큰 외곽선을 카드 외곽선으로 사용한다.

### 5.4 초기 회전 사각형 계산

`cv2.minAreaRect()`로 대략적인 카드 방향과 네 변의 위치를 구한다. 이 사각형은 최종 측정값이라기보다 외곽점들을 네 변으로 분류하는 초기 기준이다.

### 5.5 각 변의 중앙부 점 선택

각 초기 변에 대해 외곽선 점의:

- 변 방향 투영 위치
- 변과의 수직 거리

를 계산한다.

둥근 모서리의 영향을 줄이기 위해 각 변의 중앙 `12% ~ 88%` 구간만 사용한다. 초기 변과 지나치게 멀리 떨어진 점도 제외한다.

### 5.6 Huber 직선 피팅

선택된 각 변의 점들에 다음 방식으로 직선을 피팅한다.

```python
cv2.fitLine(points, cv2.DIST_HUBER, ...)
```

Huber 방식은 일반 최소제곱보다 이상치의 영향을 덜 받는다. 따라서 마스크 경계의 작은 돌출이나 누락에 더 안정적이다.

### 5.7 네 꼭짓점 복원

인접한 두 직선의 교점을 계산하여 카드의 네 꼭짓점을 복원한다.

```text
이전 변 직선 ∩ 현재 변 직선 → 꼭짓점
```

복원 결과가 다음 조건을 만족하지 않으면 잘못된 피팅으로 판단한다.

- 좌표가 유한한 값이어야 한다.
- 사각형이 convex 형태여야 한다.
- 피팅 사각형 면적이 마스크 면적의 약 `65% ~ 135%` 범위여야 한다.

### 5.8 마주 보는 두 긴 변의 평균

복원한 네 꼭짓점으로 네 변 길이를 계산한다. 마주 보는 두 변의 평균 길이를 비교해 긴 변 쌍을 선택한다.

```text
long_side_px = (긴 변 1의 픽셀 길이 + 긴 변 2의 픽셀 길이) / 2
px_per_cm = long_side_px / 8.56
```

한쪽 변만 사용하는 것보다 마스크 경계 오차와 약한 원근 차이에 덜 민감하다.

### 5.9 안전한 fallback

직선 피팅에 필요한 점이 부족하거나 결과가 비정상적이면 기존 `minAreaRect()` 방식으로 자동 전환한다.

반환되는 방식 이름:

```text
robust_line_fit
min_area_rect_fallback
bbox
```

## 6. 디버그 시각화

Swagger의 다음 API를 사용한다.

```text
POST /api/v1/measure/debug
```

현재 디버그 이미지의 카드 표시는 다음 의미를 가진다.

| 표시 | 의미 |
|---|---|
| 초록색 반투명 영역 | RTMDet-Ins가 예측한 카드 마스크 |
| 초록색 외곽선 | 마스크 contour |
| 노란색 사각형 | 직선 피팅 또는 fallback으로 복원한 카드 사각형 |
| 자홍색 두 선 | 실제 계산에 사용한 마주 보는 두 긴 변 |
| 텍스트 | 두 긴 변의 평균, 기준 길이, px/cm, 계산 방식 |

예시:

```text
avg(443.2, 439.8)px / 8.56cm = 51.58px/cm [robust_line_fit]
```

이 표시는 계산에 어떤 픽셀 길이가 사용됐는지 직접 검증하기 위한 것이다.

## 8. 현재 방식의 한계

### 원근 왜곡

카드가 카메라에 비스듬하면 두 긴 변의 픽셀 길이가 다르게 보인다. 두 변의 평균은 이 차이를 완화하지만 원근 왜곡 자체를 제거하지는 않는다.

카드만 homography로 정면 보정할 수는 있지만, 보정된 카드 좌표계에서 계산한 `px/cm`를 원본 이미지의 사람에게 그대로 적용하면 안 된다. 카드 평면과 사람 평면의 깊이가 다를 수 있기 때문이다.

### 카드와 사람의 깊이 차이

단일 이미지에서 동일한 `px/cm`를 사람에게 적용하려면 카드와 측정 대상이 카메라로부터 거의 같은 거리에 있어야 한다. 카드가 사람보다 카메라에 가깝거나 멀면 실제 키 계산에 체계적인 오차가 생긴다.

### 마스크 품질

다음 상황에서는 측정 오차가 커질 수 있다.

- 카드 일부가 가려짐
- 강한 빛 반사
- 모션 블러
- 카드가 너무 작게 촬영됨
- 카드와 배경의 색이 유사함
- 카드가 심하게 휘거나 접힘

### 데이터 규모

전체 이미지 수가 443장으로 비교적 작다. validation 성능은 높지만, 실제 배포 환경과 다른 조명·카메라·배경을 포함한 별도 test set으로 최종 성능을 확인하는 것이 좋다.

## 9. 권장 촬영 조건

측정 오차를 줄이려면 다음 조건을 권장한다.

- 카드 전체가 가려지지 않게 촬영
- 카드와 사람을 비슷한 거리 또는 같은 평면에 배치
- 카드가 이미지에서 충분한 픽셀 크기를 차지하도록 촬영
- 심한 원근이 생기지 않도록 카메라와 카드를 가능한 평행하게 유지
- 흔들림과 반사를 줄임
- 사람의 전신과 주요 관절이 모두 보이게 촬영

---

## 10. 향후 개선 후보

1. 별도 test set 구축
2. 카드와 사람의 깊이 차이를 탐지하거나 촬영 가이드로 제한
3. 긴 변 두 개의 차이가 일정 비율 이상이면 경고 반환
4. 카드의 실제 종횡비 `8.56 : 5.398`과 복원 사각형 비율을 비교해 품질 점수 계산
5. 마스크 confidence와 기하 적합도를 함께 사용한 측정 신뢰도 산출
6. 카드가 너무 작거나 가려진 경우 측정을 거부하는 품질 게이트 추가
7. 여러 실제 촬영 조건에서 기존 `minAreaRect`와 robust line fitting의 오차 비교

## 11. 핵심 요약

- RTMDet-Ins를 선택한 핵심 이유는 bbox가 아니라 카드의 실제 픽셀 영역인 mask를 얻기 위해서다.
- bbox 긴 변은 회전과 배경 포함으로 실측 기준에 부정확하다.
- `minAreaRect()`는 회전에 강하지만 마스크 극단점 노이즈에 영향을 받을 수 있다.
- 단순 주변점 평균 대신 각 변의 중앙 외곽점 전체에 Huber 직선 피팅을 적용했다.
- 네 직선의 교점으로 꼭짓점을 복원하고, 마주 보는 두 긴 변의 평균을 카드 표준 길이 `8.56 cm`에 대응시킨다.
- 피팅이 불안정하면 기존 최소 회전 사각형 방식으로 자동 fallback한다.
- 디버그 이미지에서 마스크, 복원 사각형, 두 긴 변, 계산식과 사용 방식을 확인할 수 있다.
- 이 방식도 단일 이미지의 원근 및 카드-사람 깊이 차이 문제까지 해결하는 것은 아니다.
